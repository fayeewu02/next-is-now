# 下次就是现在：从收藏抽签，到生活行动助手

## 判断

目前的 Demo 足够表达「把收藏变成一次行动」的概念，不必为了显得丰富而增加页面。相对单薄的是行动支持：抽到之后能不能真的做、缺东西怎么办、这次做不完如何续上、下次怎样更合适。

因此建议把定位定为：**帮用户在眼前的时间和条件里，完成一次来自自己收藏的小体验。** 不做另一个内容推荐流，也不急着做打卡排行榜。

以下是产品建议和待验证假设，不是已经上线的新增功能，也没有用虚构的用户数据证明需求。

## 优先融入的三个场景

### 1. 碎片时间：我只有 15 分钟

触发：等车、午休、饭后，想做点什么，但不想重新翻收藏。

玩法：沿用「我有目标」和「随机灵感」两个入口，选择 15 分钟后优先匹配一段阅读、一段播客试听、一项轻量创作。不要新增第三个首页入口。

体验重点：标明「本次只读这一段 / 听这个片段 / 完成这一小步」，区分原视频长度与实际体验时间。能拿出具体片段时再展示片段；不能取得内容时不伪造时间戳。

价值：把「需要完整一小时」拆成一个可以开始的小动作。

验证：用户是否从抽签进入开始；是否因时间过长再抽；是否在这一段结束后留下记录。

### 2. 就地开玩：按手边条件选，不临时买东西

触发：晚上在家，想做手工或吃点好吃的，但不想先采购。

玩法：手工、美食先确认已有材料；缺少主要材料时推荐明确的替代方案或换一个收藏。下一版可记住「我的常备材料」，每次只确认变化。

体验重点：缺料不只是把按钮变灰；说明缺哪样、是否能省、替换会改变什么。美食等待时间也计入，运动不提供未经核实的动作处方。

价值：降低开始成本，推荐更贴近真实生活，而不只是在内容里随机。

验证：清单导致的放弃率、替代方案采用率、需要采购的比例。

### 3. 周末小计划：让半天不被漫无目的刷手机填满

触发：周末有一两个小时，想让这段时间留下具体的东西。

玩法：在目标模式内选择较长时间，给一份可编辑的「小体验组合」，例如一件手工作品 + 一段播客；先从单件体验做好，再扩为两件组合。用户确认后才安排，不自动拉长时间。

体验重点：有需要等待的美食时，等待期间再安排阅读或播客；不把等待当成可以完全并行的保证。随时停止，不为了完成菜单增加负担。

价值：从单次抽签延伸为有起承转合的小日子。

验证：组合是否被接受、实际跳过哪一项、是否比单次抽签带来更丰富的记录。

## 后续可考虑，但不优先的场景

| 场景 | 可融入的位置 | 先验证什么 |
| --- | --- | --- |
| 做到一半，下次继续 | 日记里保存停在哪一步，回访时继续 | 用户是否经常中断长手工 / 烘焙 |
| 两个人一起玩 | 分享一张同主题体验卡，各自保留私人日记 | 是否真的需要同步开始，而不只是转发链接 |
| 周末回看自己的生活 | 月历下的简短月度回顾：作品、照片、重复兴趣 | 回看是否有意义，不先做复杂统计面板 |
| 找不到目标时表达条件 | 自填目标支持「我有纸和剪刀 / 想做不加热的甜品」 | 条件识别是否可靠，无法匹配时是否能说清楚 |
| 收藏太久，轻轻提醒 | 用户主动选择一个时间再提醒，不默认持续推送 | 提醒有没有打扰，是否能促进真实行动 |

## 实施顺序

### P0：先把核心体验做可信

1. 真实原帖关联：记录分享链接、标题和作者；没有链接就明确待关联，不能用猜测地址顶替。
2. 内容提炼：从用户授权且可读取的视频字幕 / 笔记正文生成摘要、材料、步骤；每条关键步骤保留对应原文或时间戳，给「查看依据」入口。
3. 原文不可读时降级：只展示基于封面的准备建议，不标成完整视频解析。食物配比、烹饪参数、运动动作等尤其不能补写。
4. 可执行性：明确本次体验范围、总时长、等待与必要材料；没有可靠替代就推荐换内容。
5. 轻记录：上传照片和文字都可选，纸页内完成操作，不让打卡比体验更费力。

### P1：减少下一次选择的成本

优先做碎片时间与常备材料；观察数据后再做「继续上次」。推荐理由只需解释一两点，例如「你只有 15 分钟，而且不用额外准备」。

### P2：让体验产生自然回访

周末组合、共同体验卡、月度回顾择一验证。不建议同时上社交动态、商城、排行榜和积分体系，这些会稀释「自己的收藏、自己的生活」。

## 关键指标与当前打卡口径

主指标建议是「每周产生的有意义体验」，可用用户实际作品照片、自己的感受记录、重复回访等行为辅助判断，不把点击一次按钮直接等同于完成一整件作品。

观察漏斗：抽签 → 开玩 → 体验标记 → 保存记录 → 下一次回访。再抽比例、缺料放弃、来源打不开、步骤不够明确都是诊断指标。

本次按用户要求：点击「体验已完成！」，或进入「灵感记录」，都会点亮日期。因此打卡率不等于真实作品完成率。实现中分别保存 explicit / record 两种完成来源，便于未来分析，不额外增加当前用户操作；旧记录不强行补分类。

## 内容与隐私边界

原帖网页可能需要登录，链接可用不代表已读取全文。原始分享链接可能含必要的参数，应按用户提供的完整链接使用；不绕过访问限制。站内弹层可呈现已持有的截图与摘要，通过真实链接进入小红书查看视频 / 图文；没有取得内容时不假装能在本站播放。

日记照片默认私密。未来若增加云同步或共同体验，需用户明确选择分享范围，不因为分享活动就共享所有照片。当前 Demo 仍是浏览器本地保存。

## 结论

下一步最值得投入的不是「更多按钮」，而是 **真实内容提炼 + 手边条件匹配 + 做一半可继续**。先把单次体验做得具体可靠，再用碎片时间、就地开玩和周末小计划覆盖不同生活节奏。
